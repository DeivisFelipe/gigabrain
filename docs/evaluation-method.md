## Research questions

- **RQ1 (extraction quality).** Does the multi-agent architecture keep the quality of
  requirements extracted from meetings compared to a single agent and to an LLM without
  prompt engineering?
- **RQ2 (consistency across meetings).** Over several meetings about the same system, does
  the architecture avoid repeated requirements and link changes to the requirements they
  modify?
- **RQ3 (link quality).** Are the links created between requirements (refines, depends on,
  conflicts with, supersedes) correct according to human judges?
- **RQ4 (requirement form).** Do the saved requirements follow the expected structure (EARS
  statement, user story, Gherkin acceptance criteria, no vague terms)?
- **RQ5 (cost).** What is the extra cost, in LLM calls, tokens and time?

## Compared configurations

| Configuration | Description |
|---|---|
| **GigaBrain (council)** | The Digital Twin reads the meeting one utterance at a time and drafts requirements; each draft is reviewed by the topic expert and by the quality expert (Consultative Council, which only recommends); the Twin decides (Deliberative Council) and saves it in the Repository; the expert updates its knowledge. |
| **Single agent** | The same Twin, with the same prompt and the same utterance-by-utterance reading, without the Consultative Council. Isolates the effect of the council. |
| **Plain LLM** | The whole transcript in a single request with a minimal instruction. Isolates the effect of the Twin's engineering. |
| **Rules (no LLM)** | Each stakeholder sentence becomes a requirement; class by keywords. Reference floor. |

All configurations use the same model ([deepseek-chat]) and receive the requirements already
saved in the Repository as context (so the multi-meeting scenario does not favor the council).

**Ablation:** council without the quality expert (`--no-quality`), to measure its contribution
to the FR/NFR class and the subtype.

## Data

- **Meeting dataset** (EntradasGigabrain): 18 simulated transcripts derived from PURE, with
  gold standard requirements, FR/NFR class, NFR subtype and source turns. One project
  (2005-microcare) has an empty gold standard and was excluded; 17 projects and [820]
  requirements remain.
- **Multi-meeting scenario** (built in this work): each transcript is split into 3 sessions,
  cut at the start of an analyst topic. Sessions 2 and 3 get injected utterances with a known
  answer:
  - *repetitions* (15% of the requirements): a stakeholder repeats a requirement from an
    earlier session; it should not be saved again;
  - *changes* (15%): a stakeholder changes an earlier requirement (another number or a new
    constraint); the new version should be saved and linked to the original.
  Generation is deterministic (fixed seed) and uses no LLM.

## Metrics

| Metric | Definition |
|---|---|
| Precision, recall, F1 | One-to-one matching with the gold standard by content-word similarity (Dice ≥ 0.5) |
| Class | FR/NFR correct among the pairs |
| Subtype | subtype correct among the NFR pairs |
| Trace | the requirement cites the turn where it was said |
| Unsupported | requirement whose cited utterances cover less than 30% of its words (hallucination proxy) |
| EARS, story, Gherkin, not vague | share of saved requirements that pass each deterministic format check |
| Repetitions avoided | injected repetitions that did not create a new requirement |
| Changes linked | injected changes saved and linked to the original requirement |
| Link precision | share of links judged correct by two annotators; agreement by Cohen's kappa |
| Cost | LLM calls, input and output tokens, time per meeting |

## Protocol

1. Each (project, configuration) runs [5] times; the LLM is not deterministic.
2. For each project, the mean of the repetitions is taken.
3. Configurations are compared pairwise with the Wilcoxon signed-rank test, paired by project
   (n = 17), with an exact p-value; the effect size is the paired rank-biserial correlation.
   Significance level: [0.05], [with/without] correction for multiple comparisons [Holm].
4. For RQ3, [60] links are sampled from the council runs; [two] group members judge them
   independently.

## Threats to validity

- **Construct.** The transcripts are synthetic and generated by a script that keeps the words
  of the requirements; real meetings are harder. Word matching approximates semantic
  equivalence: [validate on a manual sample]. The format checks are syntactic; they do not
  show that a requirement is correct.
- **Internal.** The prompts were tuned by the authors while looking at the KeePass project;
  [report results with and without that project]. The same model is used in every
  configuration.
- **External.** One language model and one dataset; [repeat with a second model if time allows].
- **Conclusion.** 17 projects limit statistical power; small differences may go undetected.
