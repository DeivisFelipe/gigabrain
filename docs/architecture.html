A Multi-Agent Model for Defining Software Requirements

Architecture draft — version 1

Abstract. This document describes the preliminary architecture of GigaBrain, an LLM-based agent model to support the definition of software requirements. The architecture organizes the agents into two councils: a deliberative council, in which the real Product Owner (PO) negotiates directly with a digital twin until they converge on a defined requirement; and a consultative council, responsible for investigating the technical knowledge of the platform and mobilizing domain experts on demand. The consultative council is led by a manager agent, which queries a structural knowledge base of the platform and decides, for each requested change, whether an expert already exists or must be created — in which case the new agent builds its own knowledge repository from the existing code or from external research. Figure 1 shows this architecture in detail.

1. Agent Roles

Table 1. Roles and responsibilities in the model.
Agent / resourceRole
Real POThe person who actually decides; asks questions, proposes changes and approves the final version of the requirement.
Digital TwinReplica of the real PO inside the system; debates with the human, asks the consultative council the right question and translates the answer into product language.
Leader of the Consultative CouncilThe only agent present from the start; queries the main database, decides whether an expert already exists and creates a new one when the domain is new.
Domain ExpertsAgents created on demand, one per area of the system (payments, notifications, etc.); each keeps its own RAG and answers the leader.
RAG basesA shared base with the structure of the platform and one base per expert, fed by the existing code or by research when the topic is new.

2. Example Flow: Payment Notification

  1. The real PO asks: "I want to add a notification to the payment".
  2. The digital twin passes the question to the leader of the consultative council.
  3. The leader queries the main database: is there already a payments expert?
  4. If there is, the leader asks it directly; if not, it creates a new expert, which studies the code of the payment system — and searches the web if the concept is new.
  5. The expert answers the leader, which consolidates the knowledge and returns it to the digital twin — which resumes the conversation with the real PO until both approve the final story.
